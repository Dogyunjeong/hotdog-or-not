# v0.2 — Signed upload flow, classification history, visitor session, onboarding, cookie consent

## Goals

1. Upload via signed URL to a temp bucket → backend validates, classifies, and moves the image to the destination bucket (lang-learning `ImageUploadSession` + `StorageClient.promoteFile` pattern).
2. Every classification is saved in Supabase and listed as the visitor's history.
3. Visitor identity via an httpOnly session cookie (no login).
4. First-visit onboarding overlay explaining what to do.
5. Cookie consent banner (vanilla-cookieconsent, MIT). Policy text is TBD.

## Verified on local Supabase (2026-10-10)

- `createSignedUploadUrl(path)` → `{ signedUrl, token, path }`, valid 2h; a plain `fetch` PUT with the raw file works (no SDK/keys in browser)
- Bucket `allowed_mime_types` / `file_size_limit` are enforced on signed uploads (415 / 413)
- Signed upload URLs are single-use (409 on reuse)
- `move(from, to, { destinationBucket })` works across buckets
- `info(path)` returns real `size` and `contentType`

## Data schema (migration `20261010130000_create_visitor_sessions_and_hotdog_classifications.sql`)

```sql
visitor_sessions (
  id uuid pk default gen_random_uuid(),
  storage_folder_id uuid not null unique default gen_random_uuid(), -- non-secret; scopes storage paths
  onboarding_completed_at timestamptz null,
  created_at timestamptz not null default now()
)

hotdog_classifications (
  id uuid pk default gen_random_uuid(),
  visitor_session_id uuid not null references visitor_sessions(id) on delete cascade,
  image_path text not null unique,         -- path in `hotdog-images`
  is_hotdog boolean not null,
  reason text not null,
  created_at timestamptz not null default now()
)
index (visitor_session_id, created_at desc)
RLS enabled on both, no policies (API uses service role only)
```

Storage buckets (migration `20261010130100_create_hotdog_image_uploads_bucket.sql`):

- `hotdog-image-uploads` (new, temp, private, same type/size limits as `hotdog-images`)
- `hotdog-images` (existing, destination)

## Visitor session

- Cookie `hotdog_or_not_visitor_session` = visitor_sessions.id; `HttpOnly; SameSite=Lax; Path=/; Max-Age=1y; Secure` in production
- Resolved lazily by the API on every session-scoped request: missing cookie or unknown id → create a row and set the cookie on the response
- Strictly necessary cookie → no consent required; it is declared in the cookie banner's "necessary" category

## API contracts

| Method | Path                                                  | Request                   | Response                                                     |
| ------ | ----------------------------------------------------- | ------------------------- | ------------------------------------------------------------ |
| GET    | `/api/visitor-sessions/current`                       | —                         | `{ isOnboardingCompleted: boolean }`                         |
| POST   | `/api/visitor-sessions/current/onboarding-completion` | —                         | 204                                                          |
| POST   | `/api/hotdog-image-uploads`                           | `{ mediaType, byteSize }` | `{ uploadUrl, tempImagePath }`                               |
| POST   | `/api/hotdog-classifications`                         | `{ tempImagePath }`       | `HotdogClassificationRecord`                                 |
| GET    | `/api/hotdog-classifications`                         | —                         | `{ hotdogClassificationList: HotdogClassificationRecord[] }` |

`HotdogClassificationRecord = { id, isHotdog, reason, imageUrl /* signed, 1h */, createdAt }`

### Classification flow (backend service)

1. `tempImagePath` must be `{storageFolderId}/{uuid}.{ext}` for the current session → otherwise 404 (don't reveal other sessions' files).
   The session id is the cookie's bearer secret, so it never appears in storage paths or signed URLs (review M2).
   If the temp file is gone but this session already has a record for that path, return the record (idempotent retry, review M3).
2. `info()` on temp object → 404 if missing; re-validate size/type with the shared validator
3. Download temp bytes → OpenAI vision → `{ isHotdog, reason }`
4. Move temp → `hotdog-images` (same path)
5. Insert `hotdog_classifications` row → return record with signed read URL

Failure before step 4 leaves the temp file, so the client can retry with the same `tempImagePath`.

### Client flow

pick file → shared validator → `POST /api/hotdog-image-uploads` → `PUT uploadUrl` → `POST /api/hotdog-classifications` → show result + prepend to history
