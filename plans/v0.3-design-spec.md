# v0.3 Design Spec — Responsive · Rich details · Consent · Deletion

Source: staff-ux-ui-designer (Design mode). Tech-lead rulings on open questions at the bottom.
Shared primitives/tokens are ALREADY BUILT by the tech lead (see §3 "Shared — done").

## 0. Key decisions

- ≥1024 panel: ONE panel that SWAPS list ⇄ detail ("← All photos" back). Focus/scroll restored to the same item on back.
- <1024: one `Drawer` (native dialog). <640 full-screen; 640–1023 right side sheet 28rem (`w-drawer`) full height.
- Detail content uses an @container query: 1 col in the 22rem panel/drawer, 2 cols inline under a wide verdict. One component, 3 places, no variant prop.
- Banner is blocking (`disablePageInteraction: true`) and FIRST → onboarding → app.
- Red only on the confirm button of destructive dialogs; triggers are neutral `secondary`.
- One app-wide `VisitorPrivacyProvider` (privacy domain) owns consent state, cookie-settings/delete-all/revoke dialogs, toast, reset signal. Others read `useVisitorPrivacy()` (hooks/useVisitorPrivacy.ts — contract already exists).

## 1. Flows

1. First visit Accept: page → banner (page blocked) → "Accept" → client GET /api/visitor-sessions/current (sets cookie) → onboarding if !isOnboardingCompleted → "Got it" → app; history skeleton → empty.
2. First visit Reject: banner → "Reject" → onboarding with guest step-3 copy (once per page load) → app; history shows Guest state.
3. Guest classify: pick → progress (rotating copy) → verdict + full details inline + "Not saved" note with "Turn on history". Nothing enters history.
4. Accept later: Guest state "Turn on history" (or inline note button, or Cookie settings → toggle on → Save) → `enableHistory()` → "Turning on…" → GET current → history skeleton → empty + toast "History is on. New checks will be saved here." The on-screen result is NOT saved retroactively (copy says so).
5. Select item ≥1024: click card → panel crossfades to Detail (status-enter) → focus detail h2. "← All photos" or Esc (focus inside panel) → list → focus back to the same card; panel scroll restored.
6. Select item <1024: tap card → Drawer opens → focus drawer h2. Close X / Esc / backdrop (side sheet) → focus back to card. Viewport crosses 1024 while open → close drawer, show item in panel (and vice versa).
7. Delete one: Detail → "Delete this photo" → ConfirmDialog (focus Cancel) → "Delete" → "Deleting…" (buttons disabled, Esc ignored) → success: dialog closes, detail closes (panel→list / drawer closes), item removed, focus next card (else previous, else history h2), toast "Photo deleted." Failure: dialog stays, InlineAlert, confirm reads "Try again". 404 = already gone = success.
8. Delete all (footer or history panel): ConfirmDialog listing what gets erased → "Delete everything" → pending → success: close, provider bumps `dataResetCount` → workspace remounts (classifier idle, history reload → empty), focus page h1 (tabIndex -1), toast "All gone. Your photos and verdicts were deleted." Failure: retry in place. Guest: info dialog "Nothing to delete" + "OK".
9. Revoke history: footer "Cookie settings" → prefs modal → History off (or "Reject all") → Save → library onChange (history removed) → our ConfirmDialog "Turn off history?" → confirm → DELETE current → reset like 8 → Guest state + toast "History is off and your data was erased." Cancel/Esc → `acceptCategory([...current, 'history'])` re-accept, toast "History stays on." Erase failure: retry in dialog; cancel after failure re-accepts.

## 2. Responsive layout

`PageContainer width="wide"` (built): `max-w-md sm:max-w-3xl lg:max-w-6xl`.

- <640 (max-w-md): h1+subtitle centered → preview 1:1 → verdict → details 1 col → "Try another photo" → disclosure "▾ Your history · 12" (aria-expanded, default OPEN, in-memory) → 1-col list → "Delete my data" (secondary sm) at list bottom. Footer wraps. Drawer full-screen.
- 640–1023 (max-w-3xl): classifier max-w-2xl centered, preview 4:3, details 2-col @container → history below, no collapse, `grid-cols-2 gap-3` → "Delete my data". Drawer = right side sheet.
- ≥1024 (max-w-6xl): grid `lg:grid-cols-[minmax(0,1fr)_var(--container-history-panel)] gap-8 items-start`; header spans both. Classifier max-w-2xl centered left. Panel = `Card` (padding md), `sticky top-6 max-h-[calc(100dvh-3rem)] overflow-y-auto`; panel header (h2 + count) sticky inside its scroll area; list 1 col; "Delete my data" at bottom.
- Panel detail mode: "← All photos" (secondary sm, sticky top) → hero photo 4:3 → h2 "Hotdog · {date}" (tabIndex -1) → reason → details (1 col) → "Delete this photo".

## 7. Accessibility

Focus: desktop detail → h2 (tabIndex -1); back/Esc → originating card button; drawer → h2 on open, explicit restore to card on close; after delete-one → next/prev card else history h2; after delete-all/revoke → page h1; ConfirmDialog initial focus Cancel; dialogs opened from the drawer stack in the top layer. Live regions: classifier status is the single polite region (rotation aria-hidden); toast role=status; dialog errors role=alert; history aria-busy while loading/enabling + sr "Turning on history…". Keyboard: cards are real buttons; Esc = back in desktop detail (only when focus is inside the panel), close in drawer, cancel in dialogs (blocked while pending); mobile collapse button aria-expanded + aria-controls. Semantics: panel `<section aria-labelledby>`; tables th scope + caption; meters aria-hidden next to visible "n/10"; winners never color-only. Touch ≥44px; widths in rem; sticky panel max-h in dvh; drawer safe-area bottom padding. Reduced motion: drawer slide → fade.

## Tech-lead rulings on open questions

1. Blocking banner: YES.
2. After delete-all, history consent stays (cc_cookie kept); next request lazily creates a fresh empty session. Suppress onboarding for the rest of THIS page load (in-memory); a later visit may show it again (fresh session).
3. Guest onboarding: once per page load (in-memory only).
4. DELETE one → 404 is treated as success ("already gone").
5. Comparison `metric` is already an enum key (`HotdogNutritionMetric`) with numeric values; the UI owns labels/units.
6. Detail hero uses the same signed URL; stored images are re-encoded with a 1600px long-edge cap.
7. Revoke via library prefs → onChange → our dialog → `acceptCategory` re-accept on cancel: OK. Status stays `enabled` until the visitor confirms; history must not refetch while the revoke decision is pending.
8. Accept-later does NOT save the on-screen guest result retroactively.
9. Mobile history collapse: default OPEN.

## Update (tech-lead ruling, review round)

Guest "Delete my data" is a real erase confirm, not "Nothing to delete": a guest may still have data from before (e.g. reload during the revoke prompt). Title "Delete all your data?", body "History is off, so we aren't saving anything right now.
