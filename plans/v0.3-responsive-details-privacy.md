# v0.3 — Responsive layout, rich classification details, real cookie consent, data deletion

User decisions (confirmed): guest mode on reject · photo GPS + style guess · details inline + side panel/drawer · hard delete + audit.

## 1. Responsive layout

- < 640px: single column — classifier, then history (collapsible section).
- 640–1023px: wider classifier; history below as a 2-column card grid.
- ≥ 1024px: two columns — classifier left, history as a sticky right panel (~22rem, own scroll).
- Selecting a history item shows its details in the right panel (≥ 1024px) or a full-height drawer (< 1024px).

## 2. Cookie consent + guest mode + footer

- vanilla-cookieconsent categories: `necessary` (readOnly; only the consent cookie `cc_cookie`) and `history` (the `hotdog_or_not_visitor_session` cookie).
- Banner: "Accept" (all) / "Reject" (necessary only); footer "Cookie settings" reopens preferences.
- Banner now comes FIRST (we must know if we may store anything), onboarding second.
- Server decides consent from `cc_cookie` (`categories` includes `history`) — one shared helper used by `proxy.ts` and API handlers.
  - Proxy issues the session cookie only when history consent exists.
  - No history consent → **guest**: no session cookie, no `visitor_sessions` row, no history, nothing persisted.
  - History consent + no/unknown cookie → create the session (existing upsert) and set the cookie.
- Accepting in-page: client re-requests the session (`GET /api/visitor-sessions/current`), which sets the cookie; history loads.
- Revoking `history` later (Cookie settings): confirm dialog "This erases your saved history" → erase all data (§4) → cookie cleared. Cancel → re-accept `history`.
- Onboarding: accepted visitors — persisted per session as today. Guests — shown once per visit (nothing may be stored).
- Footer: `© 2026 Dogyun · Cookie policy · Cookie settings · Delete my data`.
- `/cookie-policy` placeholder updated to list both categories (full text still TBD).

## 3. Rich classification details

One OpenAI structured-output call (`responses.parse` + zod, discriminated union), `detail: 'high'`.

```
details (schema v1) =
  | { kind: 'hotdog',
      hotdogCount, hotdogStyle { name, description },
      tastiness { score 0–10, headline, breakdown [{ aspect: bun|sausage|toppings|presentation, score, comment }] },
      ingredientList string[],
      nutritionPerHotdog Nutrition, nutritionTotal Nutrition,
      origin { source: 'photoLocation' | 'styleGuess', placeName, note } }
  | { kind: 'notHotdog',
      subject { name, description }, isFood,
      nutrition Nutrition | null,
      hotdogComparison { metricList [{ metric, hotdogValue, subjectValue, winner: hotdog|subject|tie }],
                         overallWinner: hotdog|subject|tie, verdictLine } | null }
Nutrition = { caloriesKcal, proteinG, fatG, carbsG, sodiumMg }  (estimates)
```

- Model returns everything except the comparison winners and the photo origin.
- Comparison winners are computed server-side from numbers against a fixed "average hotdog" reference (lower kcal/fat/sodium wins, higher protein wins); the model only writes `verdictLine`.
- Origin: read EXIF GPS (`exifr`) from the stored bytes → reverse geocode with OpenStreetMap Nominatim (identifying User-Agent, 1 req/s policy, 3s timeout) → keep only `city/region, country`. Fallback: model's style-based guess. Coordinates are never stored or logged.
- GPS is stripped from the stored image: re-encode with `sharp` (drops metadata) before writing to `hotdog-images`, then delete the temp object (replaces the move).
- Persist as `hotdog_classifications.details jsonb` + `details_schema_version smallint`; legacy rows (null) render verdict-only.
- Guest classification: same pipeline, returns the result with `id: null`, nothing written to `hotdog-images` or the DB; the temp object is deleted immediately.

## 4. Data deletion (hard delete + audit)

- `DELETE /api/hotdog-classifications/:hotdogClassificationId` — session-scoped; delete the image from storage, then the row. Unknown or other session's id → 404.
- `DELETE /api/visitor-sessions/current` — erase everything for the session: dest + temp storage objects in `{storageFolderId}/`, then the session row (rows cascade), then clear the cookie (`Max-Age=0`).
- `data_deletion_requests` audit table (no PII: no session id, no paths): `scope ('single_classification' | 'all_visitor_data')`, `status ('pending' | 'completed' | 'failed')`, `deleted_classification_count`, `deleted_file_count`, `failure_reason`, `requested_at`, `completed_at`.
- Storage first, DB second. Storage failure → status `failed`, rows untouched → the same request can be retried safely.
- UI: per-item "Delete" in the detail view (confirm), "Delete my data" in the footer and history panel (confirm dialog listing what gets erased). After erase-all the page resets.

## API contract changes

| Method | Path                              | Change                                                                                                           |
| ------ | --------------------------------- | ---------------------------------------------------------------------------------------------------------------- |
| GET    | `/api/visitor-sessions/current`   | `{ isHistoryEnabled, isOnboardingCompleted }` (guest → `isHistoryEnabled: false`)                                |
| DELETE | `/api/visitor-sessions/current`   | new — erase all, 204 + cookie cleared                                                                            |
| POST   | `/api/hotdog-image-uploads`       | guests allowed (path under a random guest folder)                                                                |
| POST   | `/api/hotdog-classifications`     | returns record with `details`; guest → `id: null`, not saved                                                     |
| GET    | `/api/hotdog-classifications`     | records include `details` (null for legacy); guest → `{ hotdogClassificationList: [], isHistoryEnabled: false }` |
| DELETE | `/api/hotdog-classifications/:id` | new — 204                                                                                                        |
